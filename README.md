# pouwchain — дипломний проєкт

**Блокчейн-протокол з консенсусом для розподіленого навчання нейронних мереж.**
Бакалаврська кваліфікаційна робота, спеціальність 122, кафедра систем штучного інтелекту,
НУ «Львівська політехніка». Захист — червень 2027.

Вузли мережі замість перебору хешів виконують кроки навчання нейронної моделі, а мережа перевіряє
достовірність цієї роботи. Дослідницька частина — порівняння механізмів верифікації за часткою
виявлених атак і накладними витратами.

## Стан

Готово: контракт між C++ і Python (`docs/contract.md`), канонічний хеш ваг і заголовок блоку (`worker/canonical.py`),
навчання блоку з контрольними точками та механізми перевірки A і B (`worker/`).

```sh
uv venv --python 3.12 .venv && uv pip install torch torchvision safetensors numpy pytest
.venv/bin/python -m pytest -q worker/tests
.venv/bin/python worker/worker.py task.json   # формати task.json — docs/contract.md
```

Симулятор мережі в одному процесі (`sim/`): атаки 1–5, механізми A, B, C, D, перегони за блок,
порівняння з централізованим навчанням.

```sh
.venv/bin/python -m sim.simulator --config experiments/configs/kt1_lazy.json   # раунди → experiments/runs/<name>/
.venv/bin/python -m sim.matrix --out experiments/runs/e2 --trials 5            # матриця атака × механізм (E2)
.venv/bin/python -m sim.plots accuracy experiments/runs/kt1_lazy                # графіки
```

Головна контрольна точка: **1 листопада 2026** — три вузли, навчання на MNIST, механізм верифікації B,
одна атака і перші цифри.

## Вузол (C++)

`node/` — мережева частина: заголовок блоку (236 байтів, `docs/contract.md` §2), ланцюг, перевірка блоків,
P2P по TCP і виклик Python-воркера. Залежності (nlohmann/json, PicoSHA2) CMake підтягує сам.

```sh
cmake -S . -B build && cmake --build build -j
ctest --test-dir build                 # золотий вектор, структурні правила, вибір гілки
scripts/demo.sh                        # 3 сумлінні вузли + 1 лінивий, до висоти 5
HEIGHT=8 LAZY=0 scripts/demo.sh        # лише сумлінні вузли
```

Як працює вузол:

- **Майнінг.** Бере вершину ланцюга, викликає `worker.py` з `op: train` і будує блок: хеші точок
  C₀..C_m, `ckpt_root`, заявлена точність. Перед новим раундом дообробляє отримані блоки.
- **Перевірка.** Структурні правила (зв'язок з батьком, `w_start` = `w_end` батька, K/k із завдання,
  кількість точок, `ckpt_root`), потім механізм B: q переходів, обраних приватним генератором
  валідатора, перераховуються паралельно через `op: verify_b`. Прапорець `--verify-a` додає механізм A.
- **Вибір гілки.** Найдовший ланцюг; за рівної висоти — блок із меншим хешем. Майнери з однаковою
  швидкістю закінчують раунд одночасно, і правило «хто перший прийшов» лишало б їх на різних гілках.
- **P2P.** Кадр — 4 байти довжини (big-endian) + JSON. Повідомлення: `hello`, `block`,
  `get_blocks`, `blocks`. Блок із невідомим батьком чекає, доки вузол дотягне ланцюг у піра.
- **Сховище ваг.** Спільна тека `--store`; у блоці лише хеші (рішення В2: сховище вважається доступним).
- **`--lazy`.** Атака 1: блок, у якому всі точки — копії стартових ваг, без навчання.

Результати вузла — у `--run-dir`: `chain.json`, `status.json` і файли завдань воркера.

## Структура, якою вона стане

```
node/      C++: блок, ланцюг, валідація, P2P по TCP
worker/    Python: навчання, верифікація, атаки
sim/       Python: симулятор раундів без мережі
experiments/  конфіги, CSV з результатами, графіки
store/     ваги за хешем (у git не потрапляє)
docs/      план, рішення, дослідження, контракт
```
