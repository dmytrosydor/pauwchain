# Контракт протоколу PoUW: C++ (Вузол) ↔ Python (Воркер)

Цей документ фіксує формати даних, структури та бінарне подання для забезпечення детермінізму між C++ і Python.

---

## 1. Канонічний хеш ваг моделі

Хеш ваг моделі обчислюється як **SHA-256** поверх двійкового потоку даних, сформованого за суворим порядком:

Для кожного тензора зі словника ваг (`state_dict`), впорядкованого за зростанням імені тензора (байтове ASCII-порівняння `sorted(state.keys())`):

| Поле | Тип | Порядок байтів | Опис |
|---|---|---|---|
| `len(name)` | `u32` (4B) | little-endian | Довжина імені тензора в байтах |
| `name` | `bytes` | ASCII | Символи імені тензора |
| `dtype_tag` | `u8` (1B) | — | Тег типу даних (`1` = `float32`) |
| `ndim` | `u8` (1B) | — | Кількість вимірів тензора |
| `dim[i]` | `u32` (4B) | little-endian | Розмір кожного виміру ($i = 0 \dots \text{ndim}-1$) |
| `raw_bytes` | `bytes` | little-endian | Сирі байти тензора у C-contiguous форматі |

* **Результат:** 32 сирі байти (у JSON-файлах передається як hex-рядок із 64 символів).
* **Вимога:** Тензор обов'язково переводиться в CPU та безперервну пам'ять: `t.detach().cpu().contiguous()`.
* **Чому не хеш файлу `.safetensors`:** Заголовок метаданих у `safetensors` серіалізується без детермінованого порядку ключів, що призводить до різних хешів для однакових ваг.

## 2. Заголовок блоку (Block Header)

Заголовок блоку має фіксовану довжину **рівно 236 байтів**. Усі числові поля серіалізуються у форматі **little-endian**.

| № | Поле | Тип | Розмір | Опис |
|---|---|---|---|---|
| 1 | `version` | `u32` | 4 байти | Версія формату заголовка (поточна: `1`) |
| 2 | `height` | `u64` | 8 байтів | Висота блоку в ланцюгу (генезис = `0`) |
| 3 | `prev_hash` | `bytes32` | 32 байти | SHA-256 хеш заголовка попереднього блоку |
| 4 | `task_id` | `bytes32` | 32 байти | Ідентифікатор (хеш) завдання навчання |
| 5 | `round` | `u64` | 8 байтів | Номер раунду навчання |
| 6 | `miner_id` | `bytes32` | 32 байти | SHA-256 хеш публічного ID майнера |
| 7 | `timestamp` | `u64` | 8 байтів | Мітка часу створення блоку (Unix timestamp, секунди) |
| 8 | `w_start` | `bytes32` | 32 байти | Канонічний хеш початкових ваг раунду |
| 9 | `w_end` | `bytes32` | 32 байти | Канонічний хеш отриманих кінцевих ваг |
| 10 | `ckpt_root` | `bytes32` | 32 байти | SHA-256 хеш від конкатенації хешів усіх точок ($C_0 \dots C_m$) |
| 11 | `K` | `u32` | 4 байти | Загальна кількість кроків оптимізатора в блоці |
| 12 | `k` | `u32` | 4 байти | Частота збереження контрольних точок (кожні $k$ кроків) |
| 13 | `metric_micro` | `i64` | 8 байтів | Точність або метрика якості $\times 10^6$ (fixed-point) |

$$\text{Загальний розмір} = 4 + 8 + 32 + 32 + 8 + 32 + 8 + 32 + 32 + 32 + 4 + 4 + 8 = 236 \text{ байтів}$$

* `block_hash` = $\text{SHA-256}(\text{236 байтів заголовка})$.
* `metric_micro`: використовується fixed-point (`0.9123` $\to$ `912300`), щоб уникнути недетермінізму `float` між C++ і Python.

## 3. Протокол обміну: Вузол ↔ Воркер

Вузол (C++) формує JSON-завдання, запускає процес воркера `python worker/worker.py <шлях_до_task.json>` і зчитує результат.

### 3.1. Операція навчання (`train`)

**Вхід: `task.json`**
```json
{
  "op": "train",
  "task_id": "9f2c...",
  "round": 17,
  "miner_id": "4ab1...",
  "prev_block_hash": "00c8...",
  "w_start": "7d31...",
  "K": 500,
  "k": 25,
  "batch_size": 64,
  "lr": 0.01,
  "dataset": "mnist",
  "store_dir": "store",
  "out": "run/result.json"
}
```

**Вихід: `result.json`**
```json
{
  "ok": true,
  "w_end": "b0e4...",
  "ckpt_hashes": ["7d31...", "...", "b0e4..."],
  "metric_micro": 912300,
  "steps": 500,
  "seconds": 6.42
}
```

---

### 3.2. Операція перевірки кроку B (`verify_b`)

**Вхід: `task.json`**
```json
{
  "op": "verify_b",
  "task_id": "9f2c...",
  "round": 17,
  "miner_id": "4ab1...",
  "prev_block_hash": "00c8...",
  "ckpt_from": "7d31...",
  "ckpt_to": "a91f...",
  "step_from": 125,
  "k": 25,
  "batch_size": 64,
  "lr": 0.01,
  "dataset": "mnist",
  "threshold_rule": {"kind": "relative", "alpha": 0.3},
  "store_dir": "store",
  "out": "run/verify.json"
}
```

**Вихід: `verify.json`**
```json
{
  "ok": true,
  "verdict": "accept",
  "distance": 0.0000016,
  "threshold": 0.0021,
  "seconds": 0.31
}
```

* `ok: true/false` — індикатор успішного виконання самого скрипта (без аварійного падіння).
* `verdict: "accept"/"reject"` — рішення щодо валідності перевіреного кроку навчання.

## 4. Сховище ваг (Content-Addressed Storage)

Ваги моделі не передаються по P2P-мережі всередині блоків. Блок містить лише хеші.
Самі тензори зберігаються на диску як файли формату `safetensors`:

$$\text{Шлях до файлу} = \text{store/} \langle \text{канонічний хеш ваг у hex} \rangle \text{.safetensors}$$

Оскільки ім'я файлу однозначно визначається його вмістом (content-addressed), гарантується відсутність дублювання та цілісність даних.
